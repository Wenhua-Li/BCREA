# Reproducibility details (not printed in the paper)

This file holds the engineering-level details that the paper deliberately omits:
run counts, seed values, and the instance-naming map. The paper (and its supplementary
material) carries protocol-level information only; everything below lives here.

## Campaign composition

5580 runs in total:

- 1800 pool runs = 30 instances x 6 methods x 10 seeds (run seeds 1..10),
- 1800 grid scans = one full-grid evaluation per pool,
- 1980 re-optimizations = 6 representative instances (one concentrated, one dispersed per
  scale) x 66 degradation corners (Gamma=2, delta=30%) x 5 seeds (run seeds 1..5).

## Seeds

- Instance generation: fixed before testing, starting from 8001 (18 generated instances;
  four earlier instances generated for tuning only enter no reported statistic).
  Regenerate with `PYTHONPATH=. python experiments/gen_scenarios.py --suite v3`.
- BCREA / NSGA-II scoring set: drawn once with seed 9001, fixed stratified masks per
  (delta, Gamma).
- Sampled worst-case baseline: its own fixed set of M=16 stratified realizations, seed 9101.
- Full-grid evaluation draws: seed 6000 (for Gamma<=3 this is the complete enumeration,
  12/66/220 modes; Gamma=C is the single all-degraded mode).

## Instance labels (paper <-> data files)

- Benchmark instances: i1..i12 (TEVC suite of the reference multi-solution work;
  10 x 24-target, one 48-target, one 100-target). The paper keeps these identifiers.
  Files: `data/scenarios/tevc/Info_enemy_*.mat`.
- Generated instances: gen{24,48,100}_{conc,disp}_{01,02,03}. In the paper's tables these
  are labeled C1--C3 (concentrated) and D1--D3 (dispersed) within each target scale.
  Files: `data/scenarios/generated/gen*_*.mat`.

## Budgets and grid

- Common true-decode budget D = 9000*N per run (N = number of targets).
- Decode multipliers: 1+K = 9 for BCREA (K=8 scoring scenarios), 1+M = 17 for the sampled
  worst-case optimizer (M=16).
- Evaluation grid: delta in {10,20,30,40}%, Gamma in {1,2,3,C}; operating point
  delta=30%, Gamma=2.

## What this repository distributes

- `data/results/` — the **analysis layer**: one CSV/JSON per analysis product of the
  5580-run campaign. Every table and every figure in the paper is generated from these
  files; no raw run record is needed to reproduce them.
- The **raw run records** (1800 pool `.npz`, 1800 scan `.json`, 1980 reopt `.npz`,
  ~1.6 GB) are not distributed with the repository. They can be regenerated end-to-end
  with the task lists in `data/tasks/` (see README, "Regenerating the raw campaign").
- Per-run switch-drill outcomes (instance and seed identifiers per run):
  `docs/tab_drill_per_run.tex`, regenerated by `analysis/make_tables_v3.py`.

## Task lists

`data/tasks/` contains the executable task lists (one shell command per run, seeds and
outputs explicit):

- `tasks_20261013_v3_pools.txt` (1800), `tasks_20261013_v3_scans.txt` (1800),
- `tasks_20261013_v3_reopt.txt` (3960, base list) and
  `tasks_20261013_v3_reopt_5seed.txt` (1980, the reported 5-seed protocol),
- `tasks_20261013_v3_manifest.{json,csv}` (per-run metadata for all lists).

Lines use `$PYTHON` as the interpreter placeholder; `experiments/local_run.py` substitutes
it and runs the lists in parallel from the repository root.
